# 0.1.14-wechat8079

本次在 0.1.13 的微信 8.0.79/3200 适配和账号会话协议上，调整设置入口、配置归属与出站通道。服务端协议保持兼容本 fork 的 0.1.13；上游旧 main/31853e9 仍需升级到本 fork 的会话协议服务端。

## 行为

- 微信 → 我 → 设置增加 WeChat Observatory 入口。通过 DexSQL 核验 `setting_new.MainSettingsUI`、继承链和目标布局，版本或布局不匹配时跳过插入。
- 配置和安装会话序列仅在模块私有 `no_backup` 中原子保存。微信首次前台通过显式透明 Activity 加载一次，平时仅读内存；不需要模块应用常驻。
- 微信设置保存后重建连接，桌面配置修改需要重启微信。首次后台启动且从未进入前台时，暂不连接。
- 默认出站 WS，保留旧的显式关闭设置。重连退避上限 30 秒，HTTP 后备至少间隔 5 秒，健康 WS 无出站 HTTP 轮询。
- 正常卸载由 Android 删除私有配置。新版本不向微信、公共存储或 root 临时目录保存配置；旧版本遗留文件需要执行一次清理并查看结果。
- 会话 generation 在模块私有文件中预留互不重叠的区间，微信仅在内存分配，保持跨进程重启单调性而无需在微信目录写状态。

## 安装与验收

包名 `cc.wechat.observatory`，版本号 15，沿用 0.1.13 的 fork 调试签名，可覆盖安装。

1. 覆盖安装后强行停止并重新打开微信；LSPosed 保持模块启用和微信作用域。
2. 打开微信设置中的新入口，确认地址、API Key 与 WebSocket 开关。旧的显式 `0` 不会被覆盖，需要手动开启。
3. 从旧版升级时，在桌面 Observatory 执行“清理旧版配置副本”，必要时授予其删除历史 root 镜像的权限，查看是否仍有未删除项。
4. 划掉 Observatory，微信保持运行，验证网页下发和微信收消息上报。
5. 验证断网恢复、切换微信账号、微信进程重启、模块升级及卸载重装后无旧配置恢复。

单元测试、APK 检查和 DexSQL 静态核验不能替代这些实机步骤。未通过连接手机操作 UI、实际收发或测量耗电。HMA 若拦截显式 Activity 启动仍会使首次加载失败；新版本会报告失败，不宣称可绕过任何隐藏规则。WS 保留心跳、注册续期和入站本地补偿扫描，不代表没有周期工作。

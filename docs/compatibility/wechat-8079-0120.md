# WeChat 8.0.79 · Observatory 0.1.20

本版修复发送和回执相互阻塞的问题，并让看台展示任务正文及真实处理阶段。约一分钟的用户反馈与 60 秒任务租约恢复周期相符，但不能仅凭现象确认手机端根因；需结合实机和服务端时间线验证。

## 发送通道

- 微信进程使用唯一、有界的串行发送协调器。WebSocket 接收线程独立处理心跳；重连与 HTTP 回退共享正在执行的任务及结果缓存，不能因为连接断开取消已开始的原生发送。
- 原生发送前的账号强校验保留。发送结果确认绑定准备阶段验证过的账号数据库，不再每 500ms 重复等待主线程解析账号。
- ACK 在原连接内按 1/2/4/8 秒退避重传，重传的是结果，不是消息正文。服务端对完全相同的终态 ACK 幂等确认，不重复发布消息事件。没有待确认任务时不运行 ACK 定时器。
- 服务端用独立、有界的 ACK worker 处理结果，数据库等待不占用 WS 收包线程；presence 写入最长 2 秒，ACK 操作最长 5 秒。暂时的 presence 存储故障不再直接拒绝业务结果。
- 当前任务 65 秒没有确认时关闭连接，保留原有租约。新鲜客户端活动允许直接推送；过期连接仍须探测。连接断开后的缓存结果仍需服务器重新分派该任务才能重放，因此可能等待余下租约时间，不承诺断网立即恢复。
- native 发送结果不确定时不会自动再发送正文；进程内缓存不等同于跨进程持久化的 exactly-once 保证。

## 看台

- 当前安装和在线待命安装优先显示；其他安装折叠为历史记录，不再把旧安装 ID 当成手机数量。离线历史记录不显示切换按钮。
- 网页 SSE 连接与手机在线状态分开；离线优先显示，待发数量不再掩盖离线。
- 发送记录展示收件人、正文、创建时间、等待时间、分派次数及错误，可筛选待处理、失败/未确认、最近记录和当前会话。
- pending 表示等待领取，leased 表示已分派待回执，sent 表示微信本地发送状态已确认，不代表对方已读。租约时间不是预计送达时间；结果未确认时先核对聊天记录，避免重复发送。
- 提交防重复点击，失败保留草稿；成功后展示任务 ID 并切到最近记录。网络超时结果未知时不自动重新提交。
- `GET /api/outbox` 仅管理员可读，必须指定 device 和 owner_wxid；设备管理密码不能读取消息正文。该接口不会领取任务或修改发送状态。

## 更新和诊断

同时升级服务端与同签名 APK（0.1.20，versionCode 21），强行停止并重新打开微信一次。微信私有配置保留；无需打开 Observatory 或开启关联启动。本次无新增数据库迁移。

服务端默认关闭阶段日志。联调时设置 `BRIDGE_OUTBOX_TRACE=true`，可记录 enqueue_committed、lease_committed、ws_written、ack_received、ack_committed 和 ack_replayed。仅包含任务 ID、次数和耗时，不包含消息正文、收件人或凭据。

自动验证覆盖 Go race、真实 MySQL、Android JVM、桌面/移动端交互及构建检查。手机息屏、系统冻结和网络断开条件仍需实测；WebSocket 本身不能让被系统暂停的线程继续执行。

# WeChat 8.0.79 · Observatory 0.1.19 通道恢复修复

本版针对“微信仍在后台，但看台两处都离线，有时息屏自行恢复、有时进入微信才恢复”的反馈。修复静态审查和回归测试能够确认的代码问题；目前没有本次故障时的手机运行日志，不能把每次掉线都归因于同一个原因，也不保证突破 Android/厂商的休眠或冻结限制。

## 已确认的问题与修改

- WebSocket 收包前后原先都会同步读取微信主线程账号，且等待没有上限。现在 Ping/Pong 只核对当前内存配置、账号和会话；发送消息仍校验实时账号。只读账号查询最多等待 5 秒，取消排队的迟到查询，查询结果通过配置代次及账号指针复核后才发布；不对已经执行的原生发送强行取消或盲目重试。
- WebSocket 写入原先可能无限阻塞。现在握手、Pong、poll、ACK 的写入均有 15 秒期限，超时只关闭该次写入所属的 socket，让单一 outbox worker 恢复重连。读取期限给两轮 25 秒服务端心跳预留余量，改为 65 秒。
- 服务端原先未用实际收到的 Pong 更新手机安装记录，而内部定时 poll 又可能刷新模块在线时间。现在经当前凭据/会话验证的客户端活动统一更新安装记录与模块状态，最多每 25 秒落库一次；接收时间由服务端记录，旧会话、撤销凭据及迟到事件不能刷新错误安装或倒退时间。无实际客户端回应时，内部 poll/续租不再伪装为新心跳。保持现有离线阈值。
- 监听默认网络变化、退出设备 idle、亮屏/解锁等恢复事件，在事件到达后关闭旧通道、唤醒重连等待并重置退避。5 秒合并事件，不增加定时唤醒、常驻锁或模块后台服务。
- 日志增加屏幕、idle、电池优化豁免、网络状态、深睡眠时间差等诊断；这些数据用于判断恢复条件，不能单独证明厂商冻结了进程。

## 升级

1. 同时更新服务端与 APK。只装 APK 无法修复旧后端的在线状态判定。服务器继续使用原环境变量、数据库及密钥；本次不增加数据库结构迁移。备份部署文件后，以同一源码提交构建镜像，或使用提供的 Linux amd64 服务端二进制重启原服务。
2. 覆盖安装同签名的 `wechat-observatory-0.1.19-wechat8079-debug.apk`，LSPosed 保持启用、作用域勾选微信。
3. 强行停止并重新打开微信一次，使新 hook 代码生效。0.1.18 的微信私有配置直接保留，无需重新填地址/Key，也无需打开 Observatory、目录授权或关联启动。
4. 验证亮屏后台、息屏、Wi-Fi/移动网络切换，再在不进入微信的情况下查看两处状态与发送结果。

如仍复现，请导出覆盖“息屏 → 离线 → 自行恢复/进入微信恢复”的新 LSPosed 日志，并保留对应服务端日志及时间。关注 `current account pending`、`outbox websocket unavailable`、`connection recovery event` 和 `outbox-stalled`，不需要公开 API Key。

## 系统限制与验收

[Android Doze 文档](https://developer.android.com/training/monitoring-device-state/doze-standby)说明系统可能暂停应用网络，并在维护窗口短暂恢复；[AOSP cached apps freezer 文档](https://source.android.com/docs/core/perf/cached-apps-freezer)说明进程可保留在内存中而线程被暂停。锁定最近任务、进程仍存在或微信推送仍可用，不能单独证明注入网关的主进程线程和连接持续运行。动态广播也不能保证唤醒被系统冻结的进程。

本版不要求启用 Observatory 关联启动，不持续唤起模块，不修改系统电池策略。若新日志证明系统持续暂停微信主进程/网络，需要另行评估手机端运行条件；单靠 WebSocket 重连不能在暂停期间执行代码。

验证包括 Android 单元测试、Go race/MySQL 集成测试、APK 签名与版本检查和 DexSQL 静态检查。它们不能替代一加 Android 16 / LSPosed 2.2.1 的实机息屏测试；主线合并也不代表已经完成手机端验收。

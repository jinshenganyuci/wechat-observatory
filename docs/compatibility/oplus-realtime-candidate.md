# Oplus 息屏通信候选方案（rc3 尚待真机验证）

这是测试分支，不是已证实能长期息屏在线的发布版。候选 `0.1.22-rc2-oplus/24` 的首轮长静默测试未通过，不能合并主线。本轮失败已对齐到 Oplus DeepSleep 的独立夜间联网名单及随后实际关闭移动数据的路径，现有 Hans 策略未覆盖该路径。`0.1.22-rc3-oplus/25` 增加下述 Battery 策略入口，尚待构建和真机验证。服务端在线判定和 WebSocket 重连逻辑不变。

已有 Android 16 系统日志显示：Oplus Hans 可以冻结微信分身 UID，并通过 `nwPowerDestroySocketForProc` 关闭其网络连接。微信自己的推送恢复、进程仍存在、已允许后台活动，都不证明模块的独立 WebSocket 可用。

候选只适配已分析的 PJZ110 / OP5D0DL1 固件：

```
OnePlus/PJZ110/OP5D0DL1:16/BP2A.250605.015/V.3205195-ced00f-d0523d:user/release-keys
```

系统入口严格核验 API 36、上述完整指纹以及必需方法签名。未知布局不启用；安装任一钩子失败会撤销本次策略钩子。本机运行指纹及两个 Oplus 框架 jar 的 SHA-256 已与审计输入核对一致。

## 已完成的核验与对照

以下时间均为 2026-10-18 北京时间。

| 项目 | 已有证据与边界 |
| --- | --- |
| Oplus 静态合同 | 本机 `oplus-services.jar`、`oplus-framework.jar` 经 DexSQL 核验，97/97 项通过，包含三处策略钩子及四项独立热状态门。 |
| AMS 生命周期合同 | 本机 `services.jar` 的 30/30 项通过；9 参数注册入口、完整 UID/PID、未导出过滤器及注销先删表后删过滤器的顺序均匹配。 |

旧版静默对照于 **02:23:49** 开始，窗口内不调用 ADB、不打开微信，只采样后端。事后系统日志显示 **02:28:08** 关闭该分身 socket；后端于 **02:30:04** 首次观察到 installation 离线，随即提交文件传输助手挑战。该任务 **02:31:54** 变为 `sent`，耗时 **110 秒**，仅领取一次。02:31:53 附近同时记录到微信 `MicroMsg.Alarm` 活动，这是一次恢复时间上的关联，不能推广为所有恢复均由 Alarm 引发，更不能认定模块固定周期主动唤醒。

对照使用 `dumpsys battery unplug` 模拟未接电；不代表硬件停止充电，也不是自然电池供电的完整验证。静默前确认屏幕关闭，窗口内不读取手机，因此不声称连续监测了物理屏幕状态。

rc2 首轮有效静默窗口为 **03:07:33–03:39:18，共 31 分 45 秒**。窗口内零 ADB，只按 15 秒间隔读取后端；**03:36:03（静默 28 分 30 秒）**首次观察到 installation 离线，最后一次后端活动时间停在 **03:33:51**。随即向文件传输助手提交唯一一次挑战 task 33；该任务始终 `attempt_count=0`，未被手机领取，于 **03:39:06** 被服务端既有的“最后活动超过 5 分钟”离线清理取消。提交至取消相隔 **183 秒，这是等待取消时长，不是发送延迟**。本轮未自然恢复；结束静默并执行 battery reset 后，服务端于 **03:39:23** 收到新的注册请求。

事后读取的 Oplus DeepSleep 持久历史给出了与首轮断流直接对齐的原因：**03:33:51** 转入厂商 `DEEP_SLEEP`，成功下发的夜间联网 UID 名单不含目标微信分身 UID，随后执行旧路径 `enable=false, netType=2`；**03:33:52** 再次关闭移动数据并记录 `netUnconnected`。**03:39:18** 恢复移动数据，**03:39:19** 记录 `mobileConnected`，随后服务端在 03:39:23 收到注册。该链条对应独立于 Hans 的夜间联网限制，不能仅靠 rc2 的 Hans 重要性、socket 与网络规则钩子覆盖。

本轮不能归因为 AOSP Doze 在 03:33:51 首次进入：deviceidle 历史回算的 deep idle 开始时间约为 **03:11:42**。也没有 Mac 休眠的证据：后端采样连续保持 15 秒间隔，本机同窗口无 Sleep/Wake 系统事件。微信 UID 在断流后的唤醒锁活动不证明网关线程持续运行；但本轮已有实际移动数据关闭及恢复的时间证据，无需把 reset 后状态或进程仍存在当作网络可用证明。上述原因判断仅针对这一次窗口，不推广到所有设备、断线或后台失败。

第二轮有效静默为 **03:45:48–03:55:29，共 9 分 41 秒**；期间后端样本保持 `ready` / `active`，零 ADB、不发送消息。为读取并核对上述持久历史，实验在 03:55:29 主动结束并执行 battery reset；未达到长静默验证条件，**不能计为通过**。此前 **03:43:22** 的启动尝试因前置条件不满足而中止，未产生 `quiet_start`，已自动执行 battery reset，不计入有效静默实验。结束后采证不属于静默窗口，也不作为未受干扰的自然恢复证据。两轮手机操作均使用普通 ADB，**未使用 root**。

本地证据保存在 `oplus-realtime-contract.json`、`receiver-registry-contract.json`、`rc2-protection-ack.log`、`20261018T022347-simulated-unplug.jsonl`、`20261017T190732Z-candidate-observe.jsonl`、`rc2-idle-history-after-quiet.json`、`rc2-deepsleep-failure-window.json`、`20261017T194546Z-offline-scene.jsonl` 及对应事后系统日志。静态核验、ACK 和单元测试均不能替代候选的长静默结果。

## 可选策略

- 微信设置中的“Oplus 息屏保护”默认关闭。仅网关启用、WebSocket 启用、API Key 非空且此开关打开时登记。
- 需要 LSPosed 的微信、系统框架与电池（`com.oplus.battery`）作用域；系统框架入口独立于微信工作线程，不启动网络或线程池。新增系统或电池作用域后需重启手机。
- 微信注册一个不导出的动态 receiver 作为进程生命周期标记。系统从 AMS 的真实注册表核验完整 UID、PID 和包名；配置与密钥不传入 system_server。
- 只对已登记 UID 的 Hans 重要性判断、后台断开 socket 和网络规则调整生效。网络规则走原方法设置为允许，避免系统记录与底层规则不一致。
- 热 StrictMode、热管理等级或热优先级任何一项非零，或独立热模式开启时，仍执行原厂策略；不改温度阈值、充电控制、全局冻结开关或进程的 OOM 分数。
- 关闭开关/网关/WebSocket或清除配置时注销。进程死亡、模块卸载或包更新会撤销系统内存中的登记；没有持久 UID 白名单。
- “息屏保护已登记”只表示该次登记成功，不表示正在联网。模块更新后需重启微信；已注入系统框架的 LSPosed 模块启停需重启手机，不能声称热卸载。

这不是定时解冻、常驻唤醒锁或伪造在线状态。也不覆盖尚未观测的其他厂商、AOSP freezer、断网、系统回收或设备关机情形。保持可用的后台通道可能增加耗电。

## rc3 夜间自动断网边界

Battery 入口同时核验上述完整固件指纹及电池应用 `1.2.9 / 29`，对应本地审计 APK SHA-256 `752597dd6a739ddd8bbfd9991a31465790e9b846004a96458223948d5ee32ebc`。只在全新 `SENSING` 阶段、没有既有断网或恢复工作时，调整 OEM 的 `isNotAllowDisableNetwork()` 决策。OEM 自己写入“不允许本轮断网”的正常状态，原始深睡流程继续执行；不伪造网络 API 成功，不直接操作 Netlink、移动数据或 Wi-Fi 开关。

Battery 每次做该决策时，通过临时、未导出的动态 receiver 查询 system_server。AMS 核验真实注册表中的 Battery 包、UID 1000、PID 和本次随机 nonce；只返回“当前存在有效微信保护登记且四项热状态正常”的布尔值。查询后立即注销，没有轮询、配置复制或保留连接。模块不存在、查询失败、登记撤销或热状态异常时保留原厂决策。

同一 OEM 周期中的内存标记仅用于丢弃其延迟到达的自动关闭消息（19、20，以及 11 的关闭分支），并再次核对实际无断网状态；保留所有恢复分支、混合恢复/再关闭的消息 23，以及 Modem 回调。下次原厂资格判断前清除周期标记并重新查询。关闭保护后，下一次原厂判断恢复原行为，不主动强制断开现有网络。

**移动数据和 Wi-Fi 是整机共享通道。**此项会阻止网关运行期间的本机夜间自动断网，不是只对单个 UID 的无线电豁免；可能增加息屏耗电。它不会重新开启用户手动关闭的网络，也不关闭系统其他省电或热保护策略。此设计尚须用长静默实测验证，静态契约和单元测试不能替代验证。

## 验证要求

1. 使用上述旧版离线与 110 秒挑战延迟作为对照；新版保持相同静默原则，不轮询 ADB、不打开微信，只读取后端。
2. USB 供电和电池状态分开记录。`dumpsys battery unplug` 只模拟未接电，不证明硬件停止充电；结束后必须 `dumpsys battery reset`。
3. 新版先验证关闭开关与未适配环境不影响原行为，再确认完整 UID 登记和系统策略实际生效。
4. 在同条件长时间静默后验证在线、领取与发送回执，检查自然电池供电/Doze以及撤销路径。通过前不合并主线。

# 0.1.21：以 0.1.18 为基线的精简版

本版将发送流程收回到 `baed180`（0.1.18）。手机现场记录证明，原先分钟级息屏延迟来自 Oplus Hans 冻结微信分身并关闭连接；开启该微信的完全后台行为后，原版 0.1.18 与 0.1.20 的 APK＋对应后端分别通过六分钟拔线息屏测试，各三条文件传输助手消息均约 1 秒返回成功回执。不能把恢复归因于 0.1.19/0.1.20 的额外恢复机制。完整时间与限制见 [对照记录](wechat-8079-0120.md)。

## 保留的改动

- 看台将旧安装记录默认折叠，不把多次安装 ID 当作多台真实手机；当前连接与在线待命连接仍直接显示，记录没有被删除或按账号粗暴合并。
- 新增管理员只读 `GET /api/outbox`，按设备和当前账号查询任务正文、创建时间、状态更新时间、分派次数和错误；支持待处理、失败及最近记录。沿用原有数据表与手机协议。
- 界面区分“等待微信领取”“已分派·待回执”“微信已确认发送”。回执不是收件人已读证明；租约时间不是预计送达时间。提交结果不明时保留草稿，不自动重发，切账号后丢弃旧查询结果。
- 主线程身份查询由无界等待改为最多 5 秒的只读查询，成功后复核配置代次与账号再发布；迟到结果和旧查询错误不能覆盖新配置。原生发送没有套用这种超时，避免重复发送。
- Ping/Pong 只使用已验证的内存绑定，不同步等待主线程身份反射；实际处理消息和调用原生发送前继续核对当前账号。
- 服务端真实客户端收包时间同时刷新安装与运行在线状态，写入间隔至少 25 秒，旧时间不冒充新活动；服务器自身定时拉取不再制造在线证据。保留一个合并最新收包时间的有界写入通道，避免新增的在线状态写入阻塞控制帧。
- 回执落库不以辅助在线状态写入成功为前提；数据库临时错误不冒充账号撤销；密钥和运行状态写入使用一致锁顺序。

## 清理范围

移除 0.1.19 的电源/网络事件监控、亮屏与解锁无条件关闭健康连接、额外重连唤醒状态及 socket 写入 watchdog。未引入 0.1.20 的异步发送协调器、ACK 重试和确认跟踪器、额外 ACK 数据库 worker、65 秒确认计时器、诊断 trace 开关及相关状态。新任务通知沿用 0.1.18 的新鲜探活，不用旧心跳跳过该探测。

前端沿用服务端原有可发送判定，不添加根据安装记录再次推导并禁发的覆盖逻辑。配置存储、会话分配和微信 8.0.79 原生发送适配保持 0.1.18 结构。

## 安装与兼容

APK 为 `0.1.21-wechat8079` / versionCode **22**，沿用此 fork 的持久签名，可覆盖安装此前同签名版本。覆盖后保持 LSPosed 微信作用域，强行停止并重新打开实际使用的微信（使用分身时是该分身），以加载新代码。

从 0.1.18/0.1.19/0.1.20 升级保留微信私有目录中的配置和会话数据，不需要重新填 Key，也不需要打开 Observatory、关联启动或目录授权。从更早版本升级请按 [0.1.18 配置说明](wechat-8079-0118.md)迁移。

后端请使用本版源码或配套构建产物，以显示发送记录；与 0.1.18 APK 的手机协议兼容，没有新增数据库迁移。保留现有配置、密钥和数据库，Docker 部署重新构建本版源码，二进制部署替换相同架构程序后按原方式重启。

## 验证与边界

构建流程执行 Android 单元测试与 APK 签名核验、Go race 测试及真实 MySQL 8.4 集成、桌面与手机尺寸 Playwright 用例、两套页面编译和嵌入资源一致性检查。交付目录另附最终源码提交、构建记录、APK SHA-256 和 DexSQL 验证结果。

本版 APK 的自动验证不能替代手机安装后的实测。上述六分钟手机对照使用原版 0.1.18 和 0.1.20，并非 0.1.21 APK 的手机验收；没有验证整夜待机、跨网络切换或所有厂商系统。原版同步发送结构、断线退避及已有租约恢复行为仍保留，不承诺冻结或断网时即时送达，也不保证进程死亡后的严格只发送一次。

微信进程若被厂商冻结，任一版本都无法执行心跳或发送。应对实际使用的微信允许所需后台活动；无需让 Observatory 常驻或给予 root。

# Android Module

Android 模块是 `wechat-observatory` 的微信进程适配层。它只负责微信 I/O：

- 自动识别当前微信 `wxid`。
- 注册当前微信通道。
- 观察收发消息。
- 同步联系人。
- 上传可读取的媒体附件。
- 接收服务端出站队列并在微信内发送文本。

模块不包含游戏业务、命令解析、自动回复或第三方协议登录。

当前重点适配目标是微信 Android `8.0.79 / 3200 arm64`，微信内设置入口也仅对这个经过静态核验的版本启用。微信内部类和数据库细节会随版本变化，升级微信后需要重新验证消息观察、联系人同步、媒体上传和发送路径。

## 构建

没有 Gradle Wrapper 时，使用 Android Studio 打开 `android-module` 并构建 debug APK。若仓库已经补充 Wrapper，可使用：

```powershell
cd android-module
.\gradlew.bat :app:assembleDebug
```

安装 debug APK 后，在 LSPosed 中启用模块并勾选微信作用域。

## 手机端配置

进入 **微信 → 我 → 设置 → Observatory 网关**，填写服务地址和 API Key。高级配置仍可在桌面的 Observatory 应用修改。

- Observatory 服务地址：填写自己部署的地址，默认为空
- API Key：从 Web 管理台生成
- 轮询间隔：默认 `1000`
- 出站 WebSocket：默认开启；旧版保存的 `0` 会保留，可在微信设置中打开开关
- 通讯录同步间隔：默认 `600000`
- 是否包含群聊：默认 `1`
- 是否上传媒体：默认 `0`

模块不会要求用户填写 `wxid`。切换微信账号后，模块会重新识别当前账号并用同一个 API Key 更新服务端绑定。

服务地址支持完整的 HTTP 或 HTTPS 地址并保留 `/observatory` 等路径前缀；不能包含用户名、密码、查询参数或锚点。API Key 始终以掩码显示，界面不提供明文查看入口；可以直接覆盖输入新值，保存不会清除未修改的已有值。在微信内保存后立即更新内存并重建连接；从桌面应用修改后，需要强行停止并重新打开微信。

## 配置项

| Key | 默认值 | 说明 |
| --- | --- | --- |
| `enabled` | `1` | 是否启用模块逻辑 |
| `bridge_url` | 空 | 自己部署的服务地址；缺失或无效时不连接 |
| `api_key` | 空 | Web 管理台生成的 API Key |
| `poll_interval_ms` | `1000` | HTTP 轮询出站消息间隔 |
| `poll_limit` | `1` | 每次最多拉取条数，服务端当前只租约一条 |
| `outbox_websocket_enabled` | `1` | 首选 WebSocket；显式 `0` 使用 HTTP 模式 |
| `contact_sync_interval_ms` | `600000` | 通讯录同步间隔，`0` 表示关闭 |
| `contact_sync_limit` | `10000` | 一次同步联系人数量上限 |
| `contact_include_chatrooms` | `1` | 是否同步群聊 |
| `media_upload_enabled` | `0` | 是否上传图片、语音、视频、文件等附件 |
| `media_upload_limit_bytes` | `5242880` | 单个附件上传上限 |
| `stale_message_grace_ms` | `900000` | 超过该时间的插入消息视为历史回灌 |
| `stale_message_replay_limit` | `500` | 单次微信进程最多上报的历史回灌消息数 |

## 配置与卸载

0.1.14 仅将配置和会话序列保存到 Observatory 的 `no_backup/observatory.properties`（AtomicFile 原子更新）。不再发布 Provider、不写下载目录或 root 镜像，也不往微信目录写模块配置。每次微信进程启动后首次进入前台，会短暂打开模块的透明读取窗口，把配置交给微信内存；随后无需 Observatory 进程常驻。仅后台唤起而尚未打开过微信时，模块等待首次前台加载。

透明窗口仍需要模块组件能够启动。正常包可见性过滤不等于阻止显式组件启动，但 HMA 若进一步拦截组件启动，界面会提示读取失败，需要调整该规则；不能保证绕过所有隐藏策略。

正常卸载 Observatory 时 Android 删除其私有配置及会话序列。微信中的新状态仅在内存；微信进程结束后释放，模块卸载广播可提前关闭连接；若系统或隐藏工具拦截该广播，需要重启微信彻底退出已注入代码。模块不删除服务端聊天记录或手机正常的微信聊天记录。

从旧版升级会先迁移可读的旧 SharedPreferences，再清理固定名称的旧副本。首次升级后打开桌面 Observatory，点击“清理旧版配置副本”并确认清理结果；旧版 root 镜像可能需要 root 授权。清理失败会明确提示，不能把“新版不再写入”当作“旧文件已经删除”。旧微信会话文件在微信启动时精确删除，不触碰其他微信数据。

## 注册流程

模块在微信进程可用后调用：

```text
POST /module/register
```

请求里包含 `api_key` 和模块识别到的当前微信 `wxid`。服务端会返回 Web 管理台绑定的设备名。

如果 API Key 被删除或停用，模块请求会失败，Web 管理台会显示未注册或不可用状态。

## 发送流程

1. 管理台调用 `POST /api/send/text` 创建出站任务。
2. 模块默认保持 WebSocket，由服务端在有任务时实时下发。
3. 模块在微信进程里执行发送。
4. 模块通过 HTTP 或 WebSocket ACK 回报结果。

健康 WS 期间不发出站 HTTP 轮询。断线后按 2、4、8、16、30 秒退避重连，期间 HTTP 后备请求至少间隔 5 秒。服务端使用 25 秒心跳；代理需支持 Upgrade，空闲超时应大于心跳间隔。账号、配置或租约变化会关闭旧连接并重新注册。丢失 ACK 后的重投在同一进程、同一账号会话内复用发送结果；不保证跨进程死亡的严格只发送一次。

WS 用于出站任务；收消息仍通过本地数据库插入 Hook 及时上报，保留本地补偿扫描、注册续期和联系人定期同步。WS 不是零心跳或零耗电承诺。

## 联系人和媒体

联系人快照上传到：

```text
POST /module/contacts/snapshot
```

消息上传到：

```text
POST /webhook/lsposed/message
```

图片、语音、视频、文件等附件如果能从微信本地文件中读取，会以 `media_base64` 上传。服务端保存后返回管理台可访问的 `media_url`。

如果模块只能识别消息类型但读不到附件文件，管理台会显示 `[图片]`、`[语音]` 等占位文本。

## 排查

- 模块未注册：检查 API Key 是否存在、是否停用、手机是否能访问服务端。
- Web 没有好友：等待通讯录同步，或检查 `contact_sync_interval_ms`、LSPosed 作用域。
- 收不到群消息：确认模块启用、微信已重启、群聊消息进入微信数据库。
- 发消息卡在待发送：确认当前设备对应的 API Key 已注册，当前微信账号没有切换到旧绑定。
- 配置无效：保存后重启微信；必要时重启手机。

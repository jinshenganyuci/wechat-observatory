验证了以下行为：

- 首个上传并发重试四次，均返回原任务编号；同键变更内容返回 409，未授权上传被拒绝。
- 后端及微信分身重启后，用原键和原参数重试前三份文件，仍返回原任务与消息编号，领取次数保持 1。
- 25 MiB 文件经公网反代重复上传，仍返回原编号，未创建新任务。
- 首轮 25 MiB 上限版本拒绝空文件、不支持的图片扩展名和超过当时上限的文件，未创建发送任务；最终版本使用 300 MiB 上限。
- 四个任务均经过手机 `download_verified → native_handoff → sent`；`sent` 日志在本项目源文件清理成功后记录。
- 后端四份文件的 `bytes_removed` 均为真，暂存目录中无剩余文件字节；轻量去重记录仍保留。

测试未删除微信自身保存的正式附件或聊天记录。未知结果、断电窗口和取消竞争由自动测试验证，没有在实机上传途中强行断电。未向真实微信群发送测试内容；群目标使用相同原生入口，实际群成员权限与接收方下载仍需单独验收。本次耗时是测试结果，不是网络延迟承诺。

## 300 MiB 上限版本回归

最终实现提交 `62372dcb65a73bbf82fe35b46ecadbf06d7d9372`，[完整 CI](https://github.com/jinshenganyuci/wechat-observatory/actions/runs/39125412094) 通过：Android 343 项测试零失败，Go race/MySQL 与管理台构建及浏览器回归均通过。

单文件上限统一为 300 MiB，手机暂存配额为 600 MiB，文件传输时限最长 20 分钟；小文件保持原时限。上限测试采用元数据、超大声明长度和 1 KiB 流式边界验证，**没有创建或发送 300 MiB 数据**。这些检查验证软件边界，不能替代微信对 300 MiB 实际附件的验收。

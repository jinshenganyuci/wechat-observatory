# 微信图片与 Hermes

图片使用微信原生图片消息发送，和普通文档附件区分。模块 **0.1.26 / 微信 8.0.80、3220 arm64** 首次支持 JPEG、PNG，单张最大 **8 MiB**，最多 3200 万像素、单边不超过 16384 像素。图片能力需要配套的新后端和 Hermes 插件 0.5.0；微信 8.0.79 的文字、文件适配保留，但不会领取未核验的图片任务。

## 发送

`POST /api/send/image` 使用与[文件发送](file-send.md)相同的鉴权、multipart 字段和必填 `Idempotency-Key`。上传字段仍叫 `file`，收件人可为好友、微信群或 `filehelper`。服务器检查实际图片格式，不以文件后缀代替校验。

```sh
curl -X POST "$BRIDGE_URL/api/send/image" \
  -H "X-Bridge-Password: $BRIDGE_ADMIN_PASSWORD" \
  -H "Idempotency-Key: image-example-0001" \
  -F 'device=phone-a' \
  -F 'owner_wxid=wxid_bot' \
  -F 'account_generation=1' \
  -F 'wxid=filehelper' \
  -F 'file=@/absolute/path/example.png'
```

账号与代次须从当前模块状态取得，不能直接照抄示例。返回 `outbox_id` 表示已入队；通过 `GET /api/outbox/{id}` 查询微信原生结果。图片也出现在管理台发送记录和附件暂存列表，可沿用原清理入口。管理台发送窗口有独立的图片选项。

图片复用普通文件的私有下载、SHA-256 校验、租约、一次原生发送授权、回执和幂等记录。上传响应丢失时只用原请求及原键核查；原生结果不明时不自动换键补发。相同键不能在图片与普通文件之间混用。`sent` 不代表对方已读。

## 接收与看图

在微信「设置 → Observatory 网关」开启图片接收。手机读取当前账号已可用的图片后，上报同一条图片事件；原图不可解码时，按微信自身路径规则优先读取已缓存的高清缩略图，再回退普通缩略图，并明确标注画质限制。图片不可用时显示占位信息，不假装已经识图。不会因开启此项而自动下载全部聊天原图，也不会扫描其他会话的图片目录。

后端只保存校验通过的图片，以自己生成的 `/api/media/images/{id}` 引用替代原始 Base64。下载要求管理员鉴权，不提供公开静态目录，不读取模块传入的外部 URL。专用目录为 `BRIDGE_FILE_SPOOL_DIR/inbound-images`，独立配额 256 MiB，图片保留 24 小时；过期后拒绝读取并由维护任务清理。需要持久化父目录。

Hermes 插件通过鉴权接口取图，验证大小、格式与 SHA-256，再交给官方图片缓存和 `PHOTO` 事件。识图使用 Hermes 现有的视觉模型配置；不修改核心，也不改飞书配置。取图暂时失败会保留接收游标重试；过期、损坏或超限图片给出不可读取提示，避免一张坏图堵住整个消息流。

群聊仍要求真实 `@机器人` 元数据且发送者是获准管理员。普通群图片通常不带 `@` 信息，因此不会因启用看图而自动响应群里所有图片；私聊沿用已有授权规则。具体官方命令行、定时通知用法见 [Hermes 接入](hermes.md)。

## 临时文件

- 出站：后端和手机的传输副本沿用普通文件的安全清理规则，结果不明的手机副本不会冒险删除；发送源文件不删除。图片还需原生完成回调与消息状态共同确认，缺失回调时保留待确认记录，不冒险补发。
- 入站：后端图片副本最多保留 24 小时；Hermes 本地缓存交给官方媒体缓存生命周期管理，避免模型排队读取期间被提前删除。
- 微信自身的聊天图片、缩略图、聊天记录不属于网关暂存，本项目不会清除。

GIF 动图、表情包、视频、语音识别、文件内容识别不在这次图片能力范围内。微信可能压缩发送的图片，不能把原生图片消息当作原文件逐字节传输。

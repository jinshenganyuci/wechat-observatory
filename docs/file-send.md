# 文件通知 API

`0.1.23-wechat8079` 将文件作为微信附件发送到好友、群聊或文件传输助手。需要匹配的新版服务端、MySQL、可写的私有文件目录和微信 **8.0.79 / 3200 arm64**。旧模块继续收发文本，不会领取文件任务。

## 在管理台发送

选中好友或群会话，点击输入框旁的「发送文件」。在弹窗中点击「选择文件」，或把单个普通文件拖入文件区域；确认发送对象、文件名和大小后点击「加入队列」。随后在「发送记录」查看结果，上传完成不等于微信发送完成。

上传中不能替换文件。请求结果未知时使用原文件重试，保留原幂等键；切换会话不会把旧草稿自动改发给新对象。

## 上传并创建发送任务

先通过 `GET /api/modules/status` 获取设备当前的 `device_wxid` 与 `account_generation`，通过 `GET /api/module-contacts` 获取好友或群的 `wxid`。群标识以 `@chatroom` 结尾；测试时使用 `filehelper`。

```bash
curl --fail-with-body \
  -H "X-Bridge-Password: $OBSERVATORY_ADMIN_PASSWORD" \
  -H 'Idempotency-Key: daily-report-2026-10-18-group-a' \
  -F 'device=phone-a' \
  -F 'owner_wxid=wxid_current_login' \
  -F 'account_generation=17' \
  -F 'wxid=123456789@chatroom' \
  -F 'file=@./report.pdf' \
  'https://your-server.example/api/send/file'
```

成功返回：

```json
{"ok":true,"outbox_id":123,"idempotent_replay":false}
```

这个响应只表示任务已持久化，**不表示已经发送成功**。管理台的发送记录会展示文件名、大小与发送状态。每次请求只有一个文件、一个目标会话；向多个会话通知时，分别创建请求并使用不同幂等键。

按任务编号查询结果，无需扫描最近 100 条发送记录：

```bash
curl --fail-with-body \
  -H "X-Bridge-Password: $OBSERVATORY_ADMIN_PASSWORD" \
  'https://your-server.example/api/outbox/123?device=phone-a&owner_wxid=wxid_current_login'
```

返回 `{ "item": { "id": 123, "kind": "file", "status": "sent", "attachment": { "name": "report.pdf", "size": 1234, "sha256": "..." } }, "server_time": "..." }`。实际响应还包含其他队列字段。`GET /api/outbox` 则用于列出近期发送记录。

接口使用 `multipart/form-data`，不是 Base64，也不接受任意下载链接。文件非空、单个最大 **300 MiB（314,572,800 字节）**；这是本项目当前上限，并非微信官方上限。支持 PDF、Office 文档、TXT、ZIP 和普通二进制文件。第一版拒绝微信会额外启动缩略图流程的图片/视频扩展名：`jpg jpeg bmp png tif tiff heic heif webp avi flv m4v mkv mov mp4 mts webm wmv`。后缀检查不区分大小写。

## 幂等与发送状态

`Idempotency-Key` 必填，长度 8–128 个可见 ASCII 字符。同一设备、登录账号与键下，目标、账号代次、文件名、大小、SHA-256 均相同的请求返回原 `outbox_id`；内容不同则返回 `409 idempotency_conflict`。文件字节清理后仍保留轻量去重记录。

调用方在提交前保存键与原请求参数。上传超时、连接中断、服务重启或回复丢失后，使用**原键、原参数、原文件**重试。不要因为超时就生成新键；新键表示新的发送意图。当前账号代次变更不影响对原请求的幂等查询。

发送历史仍按既有保留策略清理。历史行清理后，重试仍返回原任务编号并且不会重发，但按编号查询可能返回 404；调用方应保存已经取得的终态结果，不应把 404 当成新建发送的理由。

| 状态 | 含义 |
| --- | --- |
| `pending` | 等待模块领取 |
| `leased` | 模块已领取，尚未取得微信发送许可；不表示当前下载进度 |
| `native_started` | 已授予一次微信提交权限，等待结果 |
| `sent` | 微信原生附件流程完成，消息与附件记录核验通过 |
| `failed` | 已确认失败；不会自动新建发送任务 |
| `cancelled` | 未提交微信的任务失效或被取消 |
| `unknown` | 是否完成尚不能确认；禁止自动重发 |

`sent` 不是接收方已阅读或下载的证明。微信本身也可能独立重试它已经建立的那条消息。

手机将任务记录持久化后才申请原生提交权限。服务端只授予一次，手机在提交前再次验证当前账号；已记录发送意图的任务重启后仅核验原结果，不再次调用发送入口；尚未记录意图的下载可以在取得新租约后重新下载并首次提交。遇到断电等无法判定的窗口，优先保留 `unknown`，不能声称网络系统能保证“恰好发送一次”。原网关、API Key、安装身份及微信账号仍匹配、且重新注册成功时，同一手机恢复连接后可继续核验已记录的结果。若崩溃发生在权限已授予但消息 ID 尚未保存的窗口，可能长期保持 `unknown`。

如果服务端能够原子确认任务尚未提交微信，模块会安全取消没有取得许可的旧意图，避免它不断重新领取并阻塞队列。这个取消操作不能撤回微信已经接手的文件。

## 失败和断线后的处理

| 情况 | 处理 |
| --- | --- |
| 上传中断或上传响应丢失 | 使用原键、原文件、原参数重试，已经创建的任务返回原编号。管理台保留未确认请求；刷新后需要重新选择原文件。 |
| 手机下载失败、尚未开始发送 | 可以上报 `failed`；若失败回执也未送达，未开始的任务租约到期后可以重新领取。 |
| 开始提交的回应不确定 | 不重新调用原生发送。若服务端能原子确认未开始则安全取消，否则保留未知状态并核验。 |
| 微信已提交，但模块与后端断开 | 微信可能继续上传；手机保留任务与结果，恢复连接后核验原消息、补传同一回执。后端暂时不可达不等于文件发送失败。 |
| 服务端已确认 `failed/cancelled` | 不自动重排。原键重试仍返回原终态任务；明确要再次发送时才创建新请求。 |

结果未知时应先查看微信聊天与发送记录，不要直接换新键重发。自动恢复要求前述身份信息仍匹配；删配置、换 Key 或微信数据丢失后，不能承诺旧任务仍能自动核实。

## 查看卡住的任务与手动清理

管理台「发送记录」旁的「文件暂存」可以按后端仍有副本、未确认结果或全部文件查看任务，并翻页查找旧记录。任务详情显示最后一个已确认阶段、时间、错误、文件大小和后端副本状态。取得原生发送许可只代表模块可以调用微信，不代表文件正在上传或已经发出；当前协议未上报手机暂存占用与上传百分比，页面会明确标为未上报。

- **刷新状态**只读取原任务，不调用上传或发送接口。
- **清理后端副本**只删除本项目后端暂存的文件内容，保留任务状态、附件信息、原始发送许可及幂等记录。已明确结束的任务可清理；已持久取得原生许可的任务也可清理后端副本，因为手机在申请许可前已完整下载、校验并保存了文件，此后恢复不再下载后端副本。
- **尚未提交微信**的待领取或租约已过期任务，需要单独选择「取消未提交任务并清理后端」。有效租约中的任务受保护，不能直接删除。服务端与领取、续租、原生许可在同一记录锁内重新检查；若任务已进入下一阶段，会拒绝旧的取消操作。
- 清理请求先持久化，再删除文件；删除失败会显示「待清理」及原因，由既有清理任务重试，也可手动重试清理。重复点击或请求响应丢失不会新建发送任务。已移除的副本可重复确认，操作保持幂等。
- 后端副本清理成功不会把未确认任务变成成功或失败，也不能撤回微信消息。手机仍可用原任务核验并补回执。**手机暂存与微信正式附件不在此按钮的删除范围内**；手机是否还被原生流程使用无法确认时，继续由模块保留保护。

管理接口均使用管理员认证和明确的 `device`、`owner_wxid` 范围：

| 请求 | 用途 |
| --- | --- |
| `GET /api/files?device=...&owner_wxid=...&status=retained&limit=50` | 查看文件任务；`status` 支持 `retained`、`unconfirmed`、`all`；用响应中的 `next_before_id` 作为后续 `before_id` 翻页。 |
| `GET /api/files/{id}?device=...&owner_wxid=...` | 读取单个任务与当前可用清理操作。 |
| `POST /api/files/{id}/cleanup` | JSON 请求包含 `device`、`owner_wxid`、`mode`；模式为 `server_only` 或 `cancel_unstarted`。 |

清理响应为最新任务视图：200 表示后端副本已移除或原本已移除；202 表示清理请求已记录、文件尚未确认删除。状态冲突返回 409，应重新读取该任务，不能自动改用另一种模式。未确认列表仍保留已清后端副本的未知任务，避免把释放空间误当成发送问题已解决。

## 文件在哪里，何时清理

1. **后端**：流式接收、计算 SHA-256，保存到私有目录中的随机文件名，再建立队列记录。模块下载需要有效 API Key、当前账号会话及任务租约；没有公开文件 URL。
2. **手机**：下载到当前微信用户的 `no_backup/observatory-outgoing`，核对大小和 SHA-256，然后交给微信原生附件流程。无需外部存储授权，也无需 Observatory 应用留在后台。
3. **确认结束后**：手机先保存结果并清理本项目暂存副本，再上报回执；后端每分钟清理已确认 `sent/failed/cancelled` 的文件字节。去重和结果记录保留，防止清理后重复发送。
4. **未提交的过期任务**：最长 24 小时过期；既有账号切换和设备离线取消策略也可能提前取消任务，并不保证离线排队 24 小时。正常上传失败立即清理；进程崩溃留下、数据库无引用的后端孤立文件超过一小时后由定期任务回收。已交给微信但结果未知的文件不会按时间强删；后端副本可按上述保护规则手动释放，手机暂存仍由模块安全核验。两端均受存储配额限制，空间不足会拒绝新任务。

手机还会保留少量任务日志（最多 1024 条，满时清理已确认记录），后端保留轻量幂等记录。默认 15 天清理已发送或已取消的历史；尚有后端文件副本的任务记录会保留到副本删除后，避免文件失去查看入口。失败和未知记录当前不适用这一自动删除条件。

微信为聊天创建的正式附件、聊天记录和接收方下载文件属于微信，项目不会删除它们。卸载 Observatory 也不能自动删除微信私有目录中的数据；在微信网关设置里停用并删除配置可清理安全删除的暂存，原生任务仍可能使用的未知文件保留。不要清空微信应用数据来清理网关文件。

## 部署与升级

先用新版 `wechat-observatory-db -migrate -check` 更新表结构，**已有部署不要再次 `-seed`**；然后启动新版后端、安装匹配 APK 并重启微信。Docker 部署需持久化文件目录，数据库与文件目录一起备份。多个服务实例连接同一数据库时必须共用同一支持文件锁的目录；不要让各实例各用一份临时磁盘。

已安装支持文件发送的 `0.1.23` APK 时，仅增加本页的管理查看和清理功能不需要更新 APK；升级数据库和后端即可。

| 环境变量 | 默认值 | 用途 |
| --- | --- | --- |
| `BRIDGE_FILE_SPOOL_DIR` | `./data/files` | 私有暂存目录；Compose 使用持久卷中的 `/data/files` |
| `BRIDGE_FILE_SPOOL_MAX_BYTES` | `536870912`（512 MiB） | 后端文件总配额，包含尚未确认完成的任务 |

后端默认总配额 512 MiB，能容纳一份 300 MiB 文件；剩余空间不足时拒绝新任务，已存在请求仍可用原幂等键核查。手机暂存总配额 600 MiB，包含结果未知而保留的源文件，成功后释放。本项目不一次性将整份文件读进内存。

反向代理应允许至少 300 MiB 的文件加 multipart 开销；可配置为 301 MiB 或更高。文件上传及下载的服务端时限、管理台上传时限为 20 分钟。手机的下载与原生结果观察时限随文件大小增加，最短 2 分钟、最长 20 分钟；超时仍按既有安全状态处理，不自动重发。慢网和微信端限制仍可能使大文件失败。普通 API 的超时不变，服务端不为用户文件开启静态目录或公开下载路由。

测试验收以文件传输助手为目标，见[验收记录](file-send-validation.md)。好友和群目标使用同一原生发送入口；实机发送只测试了文件传输助手，其他目标的接收权限、微信风控与接收端下载仍需单独验收。
